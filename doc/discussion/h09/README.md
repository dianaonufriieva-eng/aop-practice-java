# Практична 9. Структура коду, функції та декомпозиція — відкрита дискусія

1. Навіщо виносити код у функцію, якщо він і так працює?
   Винесення коду у функцію прибирає дублювання, робить програму зрозумілішою (назва функції пояснює, що саме вона робить), спрощує тестування й пошук помилок, а також дозволяє змінювати логіку в одному місці замість кількох копій.

2. Чим параметр відрізняється від аргументу?
   Параметр — це змінна, зазначена в оголошенні функції (наприклад, int extraCandies). Аргумент — це конкретне значення, яке передають під час виклику функції (наприклад, 3).

3. Чому функція «бачить» не всі змінні програми?
   Через область видимості (scope): локальні змінні існують лише всередині свого методу або блоку коду. Це ізолює функції одну від одної та захищає змінні від випадкової зміни.

4. Якої довжини має бути функція?
   Фіксованої кількості рядків немає, але функція має виконувати одну логічну задачу, не мати надмірної вкладеності й легко сприйматися з першого погляду (зазвичай від кількох до кількох десятків рядків).

5. Функція змінила переданий масив, хоча цього не просили. Як так?
   У Java під час передачі масиву чи об’єкта у функцію передається копія посилання на той самий об’єкт у пам’яті. Тому зміна елементів усередині функції (array[i] = ...) змінює оригінальний масив зовні.

6. Що функція має повернути, якщо нічого не знайшла?
   Залежить від контракту: для колекцій і масивів краще повернути порожню колекцію або порожній масив (а не null); для пошуку індексу — -1; для одного значення, якого може не бути — Optional<T> або виняток, якщо відсутність результату є помилкою.
