1. **Що насправді відбувається під час x = x + 1?**
Це не математична рівність, а команда дії. Спочатку комп'ютер бере поточне значення з комірки пам'яті `x`, додає до нього 1, а потім перезаписує отриманий результат назад у ту саму комірку `x`.


2. **Чим = відрізняється від ==?**
Один знак `=` — це присвоєння (наказ «запиши це значення у змінну»). А два знаки `==` — це порівняння (запитання «чи рівні ці два значення між собою?»), яке повертає відповідь «так» або «ні».


3. **Коли брати while, а коли for?**
`for` беруть тоді, коли точно знають, скільки разів треба повторити дію (наприклад, пробігтися по масиву з 10 елементів). `while` використовують, коли кількість повторів наперед невідома і треба крутити цикл доти, доки справджується певна умова (наприклад, поки користувач не натисне «Вихід»).


4. **Чи можна написати будь-яку програму, маючи лише if і while?**
Так, абсолютно будь-яку. В теорії програмування це доведено теоремою Бома — Якопіні: для побудови будь-якого алгоритму достатньо послідовного виконання команд, розгалуження (`if`) і циклу з умовою (`while`). Усі інші цикли на кшталт `for` — це просто зручніші обгортки.


5. **break посеред циклу — зручність чи поганий стиль?**
Залежить від ситуації. Якщо це один чіткий `break` для дострокового виходу (наприклад, знайшли потрібний елемент у списку і немає сенсу шукати далі) — це нормально і зручно. Але якщо `break` запханий кудись глибоко в складну логіку або їх декілька в одному циклі, код стає плутаним і важким для читання.


6. **Як переконатися, що цикл колись завершиться?**
Треба перевірити дві речі: чи змінюються всередині циклу змінні, від яких залежить умова виходу, і чи наближаються вони до цієї умови з кожним кроком. Також треба перевірити граничні випадки (наприклад, що лічильник не перескочить потрібне значення).
