1. **Навіщо в програмуванні окремий тип для «так» і «ні»?**
Щоб не плутатися і випадково не запхати в логічну умову щось зайве. Звісно, можна було б обійтися числами 0 і 1, але булевий тип (`boolean`) робить код максимально зрозумілим: є тільки правда або брехня, без проміжних значень.


2. **Як сказати !(a && b) людською мовою?**
«Неправда, що справджуються обидві умови одночасно». Або ще простіше: «Хоча б одна з двох умов не виконується» (тобто або `a` хибне, або `b` хибне).


3. **Чим && відрізняється від &?**
`&&` — це «розумне» і ліниве І. Якщо перша умова вже виявилася хибною, другу програма навіть не дивиться, бо загальний результат і так буде `false`. А `&` — це бітова операція, яка за будь-яких обставин чесно порахує обидві частини, навіть якщо результат уже очевидний.


4. **Чому програма не падає в if (x != null && x.name == "Іван"), хоча x порожній?**
Завдяки тій самій лінивості `&&`. Програма спочатку перевіряє `x != null`. Бачить, що `x` порожній (це `false`), і зупиняє перевірку прямо на цьому місці. До спроби прочитати `x.name` справа взагалі не доходить, тому й помилка не виникає.


5. **Як запхати 32 відповіді «так/ні» в одне число?**
Через бітові маски. Звичайне 32-бітне ціле число складається з 32 комірок (нулів та одиничок). Кожен такий біт можна використати як окремий прапорець: 1 означає «так», 0 — «ні».


6. **Що швидше: n % 2 чи n & 1?**
На рівні процесора швидша бітова операція `n & 1` — вона просто дивиться на останній біт числа за один такт, тоді як ділення з остачею (`%`) потребує складніших обчислень. Правда, сучасні компілятори вже досить розумні й майже завжди самі перетворюють `n % 2` на бітову маску під час збірки.
